# FC ROM 机制对照：Contra (US)

本轮对照的是 `Contra (US)` 的已注释 6502 反汇编。你提供的 `FCEmulator_Qizhuo`
仓库中 `魂斗罗1.nes` 的 MD5 为 `7bdad8b4a7a56a634c9649d20bd3011b`，与反汇编项目要求的
US 基准 ROM 一致。ROM 只用于本地验证，不拷贝到本项目。

## 经典手感从哪里来

- **每帧固定顺序**：NMI 内按“声音 → 手柄 → 游戏状态 → 精灵绘制”执行，逻辑帧始终稳定。
- **输入分层**：`CONTROLLER_STATE` 保存按住，`CONTROLLER_STATE_DIFF` 保存本帧新按。跳跃和
  标准/F/S 枪读新按，M/L 枪才读按住，所以动作既不丢按键也不会自动黏连。
- **位移是规则，不是漂移**：户外水平速度每帧直接设为 `+1 / 0 / -1 px`；跳跃初速约
  `-5.94 px/frame`，重力每帧增加 `0.1367 px/frame`。没有通用的起步缓动和停步惯性。
- **视觉跟逻辑共用状态**：走路每 8 帧换动作格，空中翻滚每 5 帧换格；反冲、落地、
  卧倒、水中和死亡都是独立状态，不是对整张图做旋转或缩放。
- **枪口与弹道是数据表**：站立和跳跃各有一张枪口偏移表；方向由八向查表得到，
  普通子弹为 3 px/frame，连射子弹为 4 px/frame。标准枪最多 4 发、M 枪 6 发、
  S 枪 10 发，这同时控制节奏和 CPU 预算。
- **关卡不是随机波次**：每屏有人工放置的敌人、属性和地形题；另一个士兵导演器
  只从屏幕边缘间隔加入单兵，会搜索可站立地面、避免在玩家身边出生，并按武器强度和
  通关次数调整间隔。
- **规则级关卡差异**：横向丛林、伪 3D 基地、纵向瀑布、水下、机关走廊和首领房
  使用不同的滚动、碰撞、敌人表和通关状态，不只是更换背景。

## 已映射到《单词突击队》

| ROM 机制 | 当前实现 |
|---|---|
| 按住 / 新按分离 | `input.fire` / `input.firePressed` |
| 干地每帧直接设速 | `updatePlayer()` 干地立即起停，只有水洼保留惯性 |
| 八向方向表 | `resolveAimPose()` / `quantizeAim()` |
| 地面/空中枪口表 | `GROUND_MUZZLE` / `AIR_MUZZLE` |
| 武器弹槽上限 | `PLAYER_BULLET_CAPS` |
| 不缓动的单向卷轴 | `updateCamera()` |
| 固定敌人 + 边缘单兵 | 任务节拍表 + `updateReinforcements()` |
| 关卡规则切换 | `biomeIndexAt()` 现在正确返回任务 biome，风/湿滑/低重力真正生效 |

## 是否直接改 ROM

技术上可以：使用正确 MD5 的自有 ROM，通过 `cc65` 重组已注释汇编，最终只发布
IPS/BPS 补丁。但不适合作为这个网页学习游戏的底座：原 ROM/图像/音频不应随网站分发，
且动态单词、透明 UI、触控和响应式画布都需要大幅改写 6502/PPU 数据。当前采用的路线是：
**把反汇编当作可执行规格，移植机制，不移植受保护内容**。
